# Встроенный плеер

Раньше «Смотреть» уводило во внешний браузер. Теперь страница источника
открывается внутри приложения — экран `screens/player_screen.dart`,
блокировка в `core/ad_block.dart`.

## Как открывается источник

Напрямую, как в [Streambert](https://github.com/truelockmc/streambert): WebView
грузит адрес плеера источника, без промежуточных страниц на сайте или сервере —
приложение не зависит ни от того, ни от другого.

Источники и их адреса — `Config.watchSources` / `Config.embedUrl`, взяты из
Streambert (`src/utils/api.js`): `player.videasy.to`, `vsembed.su` (VidSrc),
`www.vidking.net`. Старые адреса (`vidsrc.to`, `player.videasy.net`, `2embed.cc`)
открывали плеер, но он отвечал «We couldn't find that». Если источник снова
перестанет находить фильмы — первым делом сверить адреса со Streambert.

Переходы без клика (редиректы плеера на свои домены) не трогаем. Отменяется
только клик, который уводит всё окно на посторонний сайт.

## Как устроена блокировка

Три слоя, потому что ни один не закрывает всё сам:

1. **Запросы не уходят.** `contentBlockers` в настройках WebView отбрасывает
   обращения к ~50 рекламным и трекинговым доменам, плюс типовые пути
   (`/ads/`, `/popunder`, `prebid`, `adsbygoogle`) внутри самого источника.
2. **Окна не открываются.** `onCreateWindow` всегда возвращает `false`,
   `supportMultipleWindows` и `javaScriptCanOpenWindowsAutomatically`
   выключены. `shouldOverrideUrlLoading` пропускает только белый список
   хостов — уход на посторонний домен отменяется.
3. **Страница обезвреживается.** После загрузки внедряется скрипт: подменяет
   `window.open`, снимает прозрачные ссылки-подложки поверх кадра, убирает
   `target="_blank"`, глушит `beforeunload`. Подложки подставляются заново,
   поэтому чистка висит на `MutationObserver` и повторяется раз в полторы
   секунды.

Счётчик в шапке плеера показывает, сколько попыток отбито — по нему видно,
работает ли защита и не пора ли пополнить список.

## Ограничения — честно

- **Идеальной блокировки не бывает.** Сети меняют домены каждую неделю.
  Если что-то пролезло — добавь домен в `AdBlock.blockedDomains`.
- **В вебе слой запросов не работает.** Браузер не даёт странице
  вмешиваться в чужой iframe: это запрет из соображений безопасности,
  обойти его нельзя. Попапы и переходы там блокирует сам браузер,
  баннеры внутри кадра — только расширение вроде uBlock Origin.
  Полная защита — в сборках под Windows, Android, iOS и macOS.
- **Linux** плагином не поддерживается — там остаётся внешний браузер,
  переключение автоматическое (`PlayerScreen.isSupported`).

## Что нужно для сборки

### Windows

`flutter_inappwebview` собирает нативную часть через NuGet, поэтому нужен
**NuGet CLI в PATH**:

1. Скачай `nuget.exe` с https://www.nuget.org/downloads
2. Положи, например, в `C:\nuget\`
3. Добавь папку в переменную среды `PATH`, перезапусти PowerShell
4. Проверь: `nuget help`

Ещё нужен **WebView2 Runtime** — на Windows 11 и свежих Windows 10 он уже
стоит, иначе ставится с сайта Microsoft.

### Android

`minSdkVersion >= 19`, `compileSdk >= 34` — в свежем шаблоне Flutter уже так.

### Веб

Ничего не нужно, плеер работает через iframe.

## После обновления зависимостей

```powershell
cd E:\movie-app\flutter_app
flutter pub get
flutter run -d edge
```

Под Windows — `flutter run -d windows`, но сначала NuGet (см. выше).
